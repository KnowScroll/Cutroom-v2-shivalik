The stage LLDs (`03`–`09`) apply these decisions; where a stage LLD and this record disagree, this record wins and the stage LLD is to be corrected.

## 1. Conventions

- **C1. Names.** All persisted JSON (project documents, component `meta`, Render Plan, settings, tool arguments, evidence) uses `snake_case`. Settings are `area.name_in_snake_case`. TypeScript snippets are illustrative and may use camelCase for type names only; field names in snippets must match the persisted form.
- **C2. One owner per setting.** A setting is defined in exactly one LLD and referenced by name elsewhere. Owners are fixed in section 6.
- **C3. One owner per code.** A diagnostic or error code is defined by the module that raises it. The harness relays module codes unchanged.
- **C4. Spike identifiers.** Stage drafts used local IDs (S7–S11, K1–K5, SP1–SP6, A1–A8, 1–6). The final LLDs keep their local IDs but prefix them with the stage (`R2-S7`, `R3-K1`, `R4-SP1`, `R5-1`, `R6-S7`, `R7-A1`, `R9-1`). The unified spike register lives in the R10 document. Bare `S1`–`S7` mean the spikes in `research/10-spike-evidence-log.md`.
- **C5. Runtime.** Node **26 LTS** (minimum 24.15), because the built-in `node:sqlite` module is a release candidate there and not in Node 22. `better-sqlite3` is the fallback behind the storage adapter. R0 said "Node LTS", so R0 is unchanged.
- **C6. Where data lives.** A Space lives on the WSL/Linux filesystem, never under `/mnt/c`. One Space is one production (one film with all its branches and delivered versions). Exports are copied out on delivery.

## 2. Components and rendering (R2 is the owner)

- **I1. Component `meta` is R2's shape, in snake_case:** `contract`, `size`, `duration`, `out_of_range`, `time_invariant`, `controls`, `fonts`, `probes`, plus the two additions in I2. R3's `component.meta` mirrors it exactly.
- **I2. Techniques and trusted libraries (user requirement: sprites, IK and PixiJS stay available, as the HLD says).**
  - The component contract is technique-neutral. Anything that runs in the sandboxed page behind `seek(t, controls)` is allowed: inline SVG, Canvas 2D, HTML/CSS, sprite sheets and pose atlases, layered puppets with rigs.
  - `meta.technique` is a tag list from: `svg`, `canvas2d`, `html`, `sprite_sheet`, `puppet_rig`, `pixi_scene`.
  - **Trusted library registry.** A `library` record (name, version, file hash, licence, whether it needs WebGL) lists vetted, pinned libraries. A component declares `meta.libraries: [name@version]`; the sealer injects the library script from the blob store after the shim. No library is ever loaded from the network.
  - **WebGL** is allowed only when a declared registered library needs it. Hand-written WebGL in component code stays a lint error. PixiJS v8 is the first candidate library; its admission is **pending spike S7** (speed and repeatability under software rendering with BeginFrame, and whether a seek stays order-independent).
  - **The shim gains small helpers:** `cut.ik.two_bone(root, target, len_a, len_b, bend)` for arm and leg chains, and `cut.sprite(sheet, frame)` for sprite-sheet frames. They are conveniences; components may also write their own.
  - R3's `component.representation` becomes `svg | canvas2d | html | pixi_scene | media_player | audio_score` and R3 adds the `library` kind.
- **I3. Controls are always passed complete.** The evaluator passes every declared control on every `seek`. A control declared `nullable: true` may be passed as `null`, meaning "automatic" (for example, a brow value derived from the current `expression`). An unkeyed control receives its `meta` default, or `null` if nullable.
- **I4. One track evaluator, in the compiler.** Control tracks, time maps and the camera are evaluated once, by the compiler, into per-frame tables in the Render Plan (R4). At render time Node reads the tables and sends frame packets; the host and the components interpolate nothing. R2's "trusted TypeScript module in Node" is this same module.
- **I5. Camera is applied per layer** (R2 §2.6), not as one world container (R4 D10 is changed). World and screen layers can then interleave in z-order. Per-layer `parallax` from R4 is kept.
- **I6. Masks are not layer references.** A mask is a clip shape, a gradient, or an image asset (including a baked component). R3's `layer.mask: Ref<layer>` becomes a mask specification. A live component cannot be another's matte.
- **I7. Anchor-follow layers (PROPOSED, pending a spike).** A layer may declare `follow: {layer, anchor}`. The host then seeks the leader first, reads its probe anchor, places the follower, seeks it, and captures, all within one frame. This serves held props and hand-offs across components without merging them. Until the spike confirms cost and correctness, coupled parts are authored inside one component (R7's fallback).
- **I8. Probe record.** R2's `ProbeItem` is canonical. The host adds `layer`, `stack_order` and screen-space `rect`. R9's needs (text colour, font size, fill colour) are met by the `text` block plus an optional `fill` colour. **Probe stride** is one setting, `probe.stride`, owned by R2, default 1 (every frame); R4's `probe.frameStep` is removed. The default is revisited when S4 reports the probe cost.
- **I9. Diagnostic capture modes** are an R2 engine feature used by R9: hide one element, isolate one layer, tint one element. They are requested per capture, change the work key, and can never appear in a delivery render.
- **I10. Chunk artifact.** A rendered chunk is an encoded H.264 segment at its rung's settings, with a closed group of pictures, plus a probe sidecar. Final assembly joins segments by stream copy and muxes audio; there is no second video encode. Seam correctness is **pending S4**; the fallback is a lossless intermediate per chunk and one final encode.
- **I11. Rung and grade are separate.** `rung` (`still`, `draft`, `review`, `final`) is output fidelity and belongs to R2. `grade` (`animatic`, `preview`, `final`) is input readiness and belongs to R4. A plan carries both. Delivery needs grade `final` and rung `final`.
- **I12. `document.fonts.ready` is not awaited** (R2's deviation is accepted). Fonts are installed, and the fonts Chrome actually used are checked.
- **I13. Chrome's sandbox stays on in production.** The VM image must allow it (Ubuntu 22.04 as in WSL, or an AppArmor profile on later releases). This is a deployment requirement recorded in R10.

## 3. Project model (R3 is the owner)

- **I14. Entity kinds added:** `voice_profile`, `dataset`, `media_need`, `capture_session`, `library`. Layer `params` may hold member references into a `dataset` or a `claim` (data binding), with a shared `format` record used by charts, captions and spoken numbers.
- **I15. Voice fields.** `voice_line` gains `display_text`, `spoken_text` and `token_map`. `take.timing` is `native | aligned | estimated` (R7's terms replace R3's `alignment`).
- **I16. Status vocabularies.**
  - Claim: `supported | simplification | interpretation | fiction | unverified | disputed | refuted`.
  - Rights (R7 owns the state machine): `candidate | evidence_collected | eligible | restricted | unresolved | revoked`. "Cleared" is not used; R4 and R9 say `eligible`.
  - Recipe: `seed | candidate | validated | retired`.
- **I17. Control tracks.** `control_track` gains `layer: base | derived | acting | override` (R7's four layers). Stored key times are offsets from the track's `origin` event. The `+80ms` "relative to the previous key" form is authoring sugar that the tool layer resolves before storing. Two tracks on one layer writing one control in overlapping intervals raise `CONTROL_CONFLICT` at compile.
- **I18. Readiness must not change work keys.** Each entity version has its full `hash` and a `pin_hash`, which is the hash of the document with `commitment.readiness` removed. Jobs and consumers pin `pin_hash`. Freezing an unchanged provisional commitment therefore changes no work key (R5's requirement).
- **I19. Promotion needs structural validity and authority only.** It does not require a clean compile, a passing check or a review. Corrective failures make an artifact unusable for operations that need valid input (a `frozen` compile then fails with `NOT_READY`); they do not block promotion. R6 D10 and R9 §3.5 are changed to match. Delivery is what requires every hard check to pass.
- **I20. Revision identity.** `revision_id` hashes the manifest including parents but not time or author, and `tree_hash` compares content. Only TypeScript canonicalises JSON. These refine R1 §2.2 and are recorded as an R1 revision.

## 4. Compiler and timing (R4 is the owner)

- **I21. A sound tied to a visual event follows the frame where the event appears.** `sfx_cue` and music hit points anchored to a visual event default to `sync: presented_frame`; voice and free-running music stay sample-accurate at the event time. R7's mix placement uses the sync point against that time. This refines R1 §1.5 and is recorded as an R1 revision.
- **I22. Unpinned events take the earliest time** as a documented language rule, and the timing report lists them. No `UNRESOLVED_CHOICE` is raised for a window without a preference.
- **I23. Tools exposed by the compiler:** `compile`, `plan_diff`, `timing_explain`. Rendering is requested through the scheduler-backed `render_request`.

## 5. Harness and tools (R6 is the owner of the tool catalogue)

- **I24. - **I26. The Director has no direct web search or fetch.** It calls `research_request`; only the researcher sub-loop sees web text. Search sits behind a `SearchProvider` interface with MiniMax `web_search` as the default.
- **I27. Framework.** A thin custom loop with `@anthropic-ai/sdk` as transport only, behind `ModelClient`, with SDK retries off.
- **I28. Audit logs keep everything by default** (`audit.retention_days`), with a size cap setting added.

## 7. Quality (R9 is the owner)

- **I29. Completion states** are R9's: `blocked`, `needs_material_revision`, `eligible`, `deliver`; the deliverable record's `completion_state` is `delivered | delivered_with_limitations | incomplete | blocked`. Budget exhaustion with open material findings exports the film as `incomplete`. A missing whole-film review of the exported file blocks delivery.
- **I30. The Diagnostic Evidence Bundle** schema is R9's. R6's `WorkerOutcome.evidence_bundle` and R3's `evidence` table refer to it. R3's table gains `fault_layer` and `signature`.
- **I31. Speech-to-text** runs on each accepted take and on the final file, behind a `Transcriber` interface.
- **I32. Labelling.** The always-on disclosure block and sidecar are in. Embedded C2PA signing stays off by default and is a user decision (section 9).

## 8. Revisions to accepted R1 (to be written into `lld/02` as "Revision 1")

1. §1.5: a sound effect or music hit anchored to a visual event is placed at that event's presented frame (I21).
2. §1.8: the 40/60 ms tolerance is verified against EBU R37; a 5/15 ms mux-offset tolerance is added.
3. §2.2: the revision hash covers the manifest including parents, not time or author; `tree_hash` is added; `pin_hash` is added (I18, I20).
4. §7: the RFC 8785 claim is narrowed to TypeScript only.
5. §4.3 note: for providers with no idempotency key or lookup, "reconciled with the provider" means: salvage from the local spool, book the call as presumed charged, and allow one bounded resend (R5 §2.6).

## 9. Decisions that belong to the user (collected for one batch)

1. **Audio engines** for voice, music and sound effects (already deferred by the user).
2. **Listening.** No MiniMax model accepts audio. Either voice performance and music fit stay `UNKNOWN` (rules and transcripts only), or a second provider with audio input is added for an `AudioReviewer`.
3. **Voice policy:** no cloning or imitation of real people; stylised voices for historical figures; disclosure; provenance. Also whether the creator's own voice may be cloned with consent.
4. **AI-content labelling of exports:** keep embedded C2PA signing off, or turn it on (needs a certificate; YouTube then applies a label that cannot be removed). Whether a visible notice for synthetic voices is the default.
5. **ShareAlike media** (CC BY-SA): acceptable or not. Default in the draft: not.
6. **A contact identity** for the User-Agent that Wikimedia and the Art Institute of Chicago require. This is personal information and is never sent without the user's say.
7. **Capturing third-party software screens** for tutorials: on what basis.

### 16.5 Decisions from spike batch 3

Batch 3 ran the two spikes the independent review asked for before the freeze: patch authoring on a 184-entity project (`R3-K2`, 588 runs) and the Director's segment restart (`R6-S10`). The full results are in [the batch 3 evidence file](../research/evidence/b3-patches-and-restart.md).

**What was found.** The patch operations hold up: with a transport that keeps JSON types, 95% of runs reached exactly the expected project state, 88% of first patches were valid, 96% were valid within one repair and 98% within two, at $0.0006 (MiniMax-M3.1-Flash) to $0.0015 (MiniMax-M3) per edit. **But the MiniMax endpoint damages free-form tool arguments.** The model writes a tool call as XML-like elements and the endpoint builds JSON from them using the tool schema, so any value the schema leaves untyped loses its type: numbers arrive as strings, arrays as `{"item": ...}`, empty containers as `""`, and a nested key that shares its name with a tool parameter can land one level up. Between 31% and 59% of structured patch calls were damaged, and the model cannot repair it because it never sees the damage. Sending `ops` as one string of JSON text removed the damage entirely (0 of 312 calls), at the price of a 1.9% rate of JSON syntax errors. The segment restart lost no state in 9 of 9 runs at a context of 13,000 to 17,000 tokens; without the working notes, a half-finished step led to rework and a wrongly reasoned waiver in 2 of 2 runs.

| # | Decision | Documents |
|---|---|---|
| J1 | **Tool arguments are encoded per provider, by the model adapter.** The tool catalogue stays logical: each tool's input is one Zod schema, as before.
